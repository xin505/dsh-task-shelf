# DSH Task Shelf 1 · 1.1.1 安全修订试用说明

目标：Windows DSH 0.2.1-rc.3、0.2.1-rc.5、0.2.2-rc.1 或 0.2.2-rc.2。此包为社区预发布版本。本次修复压缩旧请求重放时遗漏来源归属和资料夹版本复核的问题；界面、兼容范围和任务数据格式沿用 1.1.0。

## 安装

先从本仓库 Releases 下载安装用 ZIP，解压到长期保留的位置。

1. DSH 侧栏“插件”→“添加插件”→“安装第三方插件”。
2. 在“包名或地址”粘贴 解压后的 `dsh-task-shelf-1.1.1` 文件夹完整路径。目录中应直接包含 `package.json`、`cordis.patch.yml` 和 `lib`。
3. 按宿主提示安装；若提示重启，正常重启 DSH。
4. 确认已启用，侧栏应出现“任务资料夹”。

另提供 `.tgz` 归档供保存和分发。优先从本地包目录安装，不用 npm CLI 管理桌面 profile，也不需要修改宿主文件或放宽版本检查。

1.1.1 修订时自动化验证使用 DSH 0.2.2-rc.1；2026-11-12 补测了 0.2.2-rc.2。两次均使用真实隔离 Web 运行时，日常桌面 profile 的完整验收尚未完成。若实际界面或安装提示不同，记录版本和提示即可。

## 新版操作

- 默认阅读资料夹；点击标题旁编辑按钮或“下一步”右侧“编辑”，修改后点击“保存修改”。取消编辑会放弃本次修改并提示确认。
- 相关会话的箭头打开会话；右侧更多菜单用于设置主会话和取消关联。
- “会话交接”页签负责选择来源、压缩和生成；切换回概览不会清空本窗口交接内容。
- “工具”菜单提供备份、导入和诊断；列表底部进入回收区。窄窗口通过“返回资料夹列表”切换。

## 第一轮试用

DSH Task Shelf 1 的包版本为 `1.1.1`。先通过“工具 → 导出备份”导出任务备份，再使用 DSH 插件页的本地安装流程选择新目录；若宿主拒绝重复安装或仍使用旧链接，先停用并卸载旧插件，再安装新包。保持只有一个启用条目，不修改宿主配置。

升级前请保留旧安装包。安装后在右上角“工具 → 查看诊断”应显示“DSH Task Shelf 1.1.1”，诊断报告 version 为 `1.1.1`、build 为 `1.1.1-replay-validation`。

DSH Task Shelf 1 继续兼容旧数据 schema 1/2，不新增迁移。资料夹的跨区关联沿用上一修订的 schema 2，早期包不能读取。若需要可回退，更新前应停用插件，另存 `$DSH_HOME/task-shelf/state.json` 及存在的 `state.json.previous`，再启用新包。回退须先保留当前文件，再核对格式兼容性；JSON 导入是新增复制，不是覆盖恢复。交接准备与压缩不改变上述任务数据格式。

1. 选择已存在的工作区，新建“插件开发与试用”资料夹。
2. 写一句下一步，点击“保存修改”。
3. 点击“关联会话”，用“会话来源工作区”选择当前或其他工作区，再关联其中的会话。关联不会移动原会话。
4. 设为主会话，点击“继续会话”检查跳转。
5. 返回资料夹，导出备份，再重启 DSH 检查内容是否保留。

会话标题缓存不可用时显示 ID；归档会话需先在 DSH 中取消归档，插件不代为取消归档。

## 跨工作区、跨会话交接包

1. 打开任意资料夹，先保存便签修改。切换到“会话交接”页签，展开工作区并勾选里面的会话，不需要先在“相关会话”关联。
2. 可从多个工作区合选 1–5 段会话。折叠工作区或筛选名称不会取消选择；“已选”区域可随时移除来源。选择压缩方式后点击“生成交接包”。未经超限压缩的文字直接进入包内，所选各段合并成一个包。
3. 单段超过 12,000 字符时，按所选方式自动压缩该段。处理后合计仍超过 30,000 字符，会显示各段压缩前后大小，等待你点击某一段的“压缩这一段”；不会代你选择。一次不够可继续选同一段或其他段，也可移除来源后重新生成。
4. 容量符合后默认并排显示：左边保留来源编号，右边为易读版。来源是原文、AI 摘要或本地精简都会标注。两份可以分别编辑，右上角可切换视图；重新生成或再压缩会重新生成两份，并在覆盖已有编辑前提示。
5. 在“复制、下载或带入会话的版本”选择需要的一份，默认易读版。复制和后续草稿操作使用所选版本；下载左侧记录得到 Markdown，下载易读版得到 TXT。
6. 在“交接目标工作区”选择接收材料的工作区，可以与所有来源都不同。点击“带入新会话草稿”，使用 DSH 原生入口填入材料，不发送。若宿主复用已有空会话，追加文本而不覆盖旧草稿。要交给已有讨论，请复制交接包后自行粘贴到该会话。
7. “在新会话整理摘要”是另一个可选入口：只准备整理提示词，发送后才调用会话模型。它与上方直接调用模型的“AI 压缩”不同。

来源与目标均限当前 DSH 环境已登记的工作区。工作区新建或删除后，可重新打开插件面板刷新目录。来源会话移到其他工作区后，请从“已选”中移除旧来源，再从新工作区重新勾选。来源或目标被移除时会显示错误，不自动改投其他工作区。上方“相关会话”的跨区关联与主会话功能仍可独立使用。

DSH Task Shelf 1 不再按“最近 12 条、每条 1000 字”预先截取。读取当前有效历史中的用户/助手文字后判断容量；不包含系统提示、思考、工具结果、附件，也不会恢复被替换隐藏的历史。若 DSH 本身已压缩历史，不能凭此恢复更早原文。读取已持久化前缀，不强制刷新活跃会话，正在生成或尚未落盘的内容可能不在包内。

容量按 Unicode 字符计量，不是模型 token 上限。单段 12,000，整包 30,000（按两份较大者，含标题与来源说明）；生成后的人工编辑上限仍为每份 50,000。另有读取保护上限：每个来源 20,000 个日志事件、逻辑日志 8 MiB，超过时会拒绝读取，而不是无上限加载再压缩。任一来源失效或不可读时整批拒绝，不静默丢弃来源。归档来源可以读取。

## 两种压缩方式

| 方式 | 优点 | 代价与限制 |
| --- | --- | --- |
| 本地精简（默认） | 快速、免费、不把内容发送给模型 | 保留约前 35% 与后 65% 的目标字数，省略中间，可能丢失关键内容；不是语义摘要 |
| AI 摘要 | 提炼目标、决定、限制、未解决问题和下一步 | 内容交给界面显示的 DSH 默认模型；可能收费、遗漏或误解，需核对 |

选择 AI 后，点击“生成交接包”会对单段超限来源自动发起摘要请求；点击某段“压缩这一段（AI）”会压缩该段。没有单段超限时，生成不调用模型，合计超限仍等你选。模型在 DSH 中配置；界面可刷新模型信息，默认模型发生变化会要求刷新，不悄悄改投另一个模型。

AI 使用官方 LLM 服务，不运行代理、不执行工具、不改写源会话。单段原文最多 120,000 字符，长文本按 10,000 字符分段提炼再合并，所以可能多次调用。每段模型输入还会按上下文容量保守检查；整次压缩最多等待 180 秒。摘要不符合长度要求、没有正常结束、来源失效或模型失败时保留原内容，不把截断输出当成完整摘要。插件不自动重试失败调用；宿主自身的重试策略仍由 DSH 管理。超时或失败可能已经计费，可“刷新压缩结果”查看状态，再决定重试或改用本地精简。

后端临时准备最多 8 份、共 24 MiB，30 分钟到期后在下次请求清理。它们仅在插件内存，不写到聊天日志或任务备份；插件重启后失效。可继续下载窗口中已有编辑稿，但再次压缩需要重新生成。

交接编辑稿只在当前窗口内存中保留，切换资料夹后可返回继续编辑；刷新、关闭或重载会丢失，关闭前请复制或下载。它不进入任务 JSON 备份，也不会自动上传。生成后改变会话选择或本地资料夹版本会要求重新生成；原会话后续变化不会自动更新旧包，请按需要重新生成。发送交接材料会将其中的会话内容交给所选模型，确认后再发送。

## 启动自检说明

每次 DSH 加载并启用此插件时自动运行一次，不必打开面板触发。打开“任务资料夹”后，在右上角选择“工具 → 查看诊断”查看各项结果与检查时间。页面刷新读取同一轮启动结果，不会重复写入探针；重启 DSH 或重新加载插件才产生新一轮结果。

- 检查数据文件可读与格式有效、上一份备份可读，以及同一目录内独立临时文件的写入、读回和清理。首次使用没有数据或备份属于正常情况。
- 最近一次报告保存在 `$DSH_HOME/task-shelf/health-latest.json`，每次覆盖，不无限积累。界面可“导出诊断报告”。报告仅含版本、时间、结果和固定提示，不含路径、标题、聊天、便签或会话标识；不上传。
- 报告写入失败时，界面仍可导出本次结果；磁盘上的旧报告可能过时，请看检查时间。
- 检查发现异常时不自动修复、不删除数据、不自动重启宿主。数据文件仍由原有读写校验保护。
- 这是启动时的局部自检，不是持续监控或数据持久性保证。不会探测模型、网络、全部关联会话，也不能检测插件未安装、被禁用、完全加载失败或 DSH 自身崩溃；这些情况查看 DSH 插件页错误提示。

## 日常保存注意事项

- 保存期间继续输入的文字会保留，但需要再次保存。
- 双窗口冲突时保留草稿，可复制后重新加载；不强行覆盖。
- “结果待确认”时先查询结果，必要时重试原操作。24 小时后需先核对已有记录，避免重复新建。
- 当前窗口切换面板保留草稿；窗口关闭、宿主强退或插件重载不保证恢复未保存草稿。
- 导出包含全部资料夹、回收区、便签和会话引用，不包含聊天原文。
- 导入经过预览和确认，生成新 ID、保留现有内容，不覆盖同名资料夹。同一导出包重复导入会阻止；重新导出是新包，不作内容合并。
- 导入只支持当前 DSH 中仍能验证的工作区和会话。跨机器、工作区重建或引用缺失会使整批导入被拒绝，旧数据不变。

## 停用、恢复与反馈

从 DSH 插件页停用或卸载 `dsh-task-shelf`。源码没有卸载清库逻辑，仍建议先导出。

提示数据损坏时停止写入，尝试“导出上一份备份”，保留 `state.json` 和 `state.json.previous`。不要删除整个 `.dsh`。恢复上一代会丢失最近一次变更，需先停用插件、备份原文件，再由维护者检查恢复。导入功能不会覆盖损坏文件。

反馈请记录插件版本、DSH 版本、操作步骤、预期结果和实际提示。截图可遮盖标题，无需公开完整备份或聊天。

后续新包会附修改说明；本版不自动更新，请从仓库 Releases 获取更新。

兼容范围允许更多 0.2.x 正式版，以及 0.2.1 与 0.2.2 的后续 RC；测试版本记录为 0.2.1-rc.3、0.2.1-rc.5、0.2.2-rc.1 和 0.2.2-rc.2，具体插件版本与范围见测试记录。其他版本可安装不等于已经测试；0.2.3-rc 等新的预发布版本仍需单独加入。
