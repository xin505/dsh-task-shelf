# 验证、兼容与发布方案

状态：方案 v0.2 的待执行验收。本文所有数字都是初始验收目标，没有已通过的测试结论；容量及提交语义以 [V1-PLAN.md 第 5–6 节](V1-PLAN.md#5-数据模型与限额) 为准。

## 1. 测试环境

采用独立 DSH_HOME、独立 profile／浏览器用户数据与合成会话。桌面应用是否支持完整隔离必须先验证；若不支持，使用隔离的操作系统账号或虚拟机，不以用户日常 profile 试错。

环境报告必须记录：DSH 精确发行版本与源码标识（可获得时）、Node／Electron 版本、插件版本与 commit、操作系统、UI 形态、其他启用插件、样本规模、测试时间与硬件。

不需要真实 API key 的测试不调用模型。需要确认真实会话行为时，把合成测试与有限真实回合验证分开记录。

## 2. 兼容矩阵

| 宿主／平台 | 当前状态 | 支持策略 |
|---|---|---|
| Windows 官方桌面端，用户实际版本 | 待确认版本、未测试 | 首个目标 |
| 同一 DSH 版本的 Web／Chromium | 未测试 | 通过独立安装及 UI 测试后支持 |
| macOS／Linux | 未测试 | 不列为已支持 |
| 下一 DSH 版本／nightly／master | 未测试 | 用于适配探测，不开放普通用户自动升级 |

首个发行版精确声明一条已验证版本。后续目标是维护“当前已验证版本 + 上一条已验证版本”，但需要真实维护能力，不先承诺无限向后兼容。

官方当前规则：engines.dsh 存在时决定准入，未声明时才使用相应 DSH peers 检查。因此不能在 engines.dsh 写宽范围、指望较窄 peers 自动补救。精确声明和安装实测必须一致。

运行时能力检查只是第二层防御，无法补救检查代码之前的导入失败。绝不把强制兼容豁免作为默认安装步骤。

## 3. 验收矩阵

| ID | 场景 | 通过条件 |
|---|---|---|
| L01 | 冷启动与插件关闭时启动 | 宿主可进入对话，插件关闭时无自身后台活动 |
| L02 | 安装／启用／停用／卸载／重装 | 每一步符合宿主语义；需要重启时明确标记；数据不被误删 |
| L03 | 反复启停或重载 20 次 | 不重复注册入口、监听或路由；资源释放可观察 |
| L04 | 模块导入／初始化故障 | 记录真实宿主影响；外部恢复可用；不得伪称无影响 |
| D01 | 双窗口同时编辑同一资料夹 | 一次成功、另一次显式冲突；不无声覆盖 |
| D02 | 提交前写入中断、存储失败 | 保留旧完整数据；失败操作不显示保存成功；提交后响应丢失另按 D06 确认结果 |
| D03 | 坏数据／未知 schema | 只读恢复或明确拒绝；不重置为空 |
| D04 | 升级迁移中断后重启 | 原数据或已校验的新数据可用，不出现半迁移状态 |
| D05 | 回退旧插件 | 未知新 schema 不写入；备份恢复流程可执行 |
| D06 | 提交成功后响应丢失／宿主重启 | UI 显示结果待确认；原 operationId 能查询到提交结果，同请求重放不重复执行，不清掉后续草稿 |
| D07 | 幂等标识冲突、回执到期或配额满 | 同标识不同请求拒绝；过期不自动认定未执行；有效回执不被提前驱逐，查询与导出仍可用 |
| D08 | 合法大资料夹超过普通请求大小 | 引用分页读取、增量编辑均可完成；普通请求／响应及编码后的传输块不超过 64 KiB |
| R01 | 文件移动、会话删除、消息未加载 | 区分确认失效和暂不可验证；其余引用继续可用，摘录与备注不丢失 |
| R02 | 跨工作区引用及路径穿越 | Host 拒绝非法目标；合法目标仍可访问 |
| R03 | 跨环境会话／消息／文件映射 | 原 ID 不直接成为本地绑定；不按标题绑定；会话映射后消息单独验证；同名文件需确认目标工作区与路径 |
| R04 | 导入伪造 originId、绑定或状态 | 来源标识不产生授权；所有绑定重新校验；不能靠导入 resolved 状态绕过检查 |
| I01 | 导入预览／提交前取消／重复导入 | 提交前取消不改变正式资料夹集合；暂存可清理；重复包默认阻止，显式副本产生新 ID；无任意路径写入 |
| I02 | 完整 JSON 备份往返 | 含回收区和全部文本的最大合法数据集导出不超过 32 MiB，并可在有足够容量的隔离存储中导入；校验内容与引用关系，不要求新本地 ID 相同 |
| I03 | 分块导入缺块、重复块、坏摘要 | 未完整校验不能提交；重传不重复追加；超限输入在解析前拒绝，暂存及候选数据受独立限额约束 |
| I04 | 导入提交中断／并发编辑／提交后取消等待 | 重启后原集合或全部新记录可用，无半批新增；不覆盖并发编辑；取消等待不显示已撤销，原标识可查最终结果 |
| I05 | 预览后容量或授权发生变化 | 提交前重新检查并整体拒绝不合法提交，原数据完整保留，不采用过期映射或配额快照 |
| I06 | 脱敏导出与待关联内容 | omittedFields 与置空字段一致；未绑定引用及摘录备注仍可保留；Markdown 明示只读用途，不宣称完整恢复脱敏副本 |
| I07 | 普通重试回执过期后重复导入 | 对仍保留导入记录的包，长期导入回执仍能识别重复；清除记录后明确去重边界，不承诺无限历史追踪 |
| U01 | 两窗口／两工作区选择当前任务 | 当前任务互不串用；入口显示目标名称；没有选择则弹选择器，不自动加入最近任务 |
| U02 | 加入请求期间切换工作区或删除目标 | 请求目标固定，Host 再次校验；失败不误加到新工作区／新资料夹，失效选择清除 |
| U03 | 设置、取消关联与删除主会话 | 主指针只指向同资料夹已绑定会话；取消关联时原子清空；目标失效时提示选择，不自动换会话 |
| U04 | 仅有文件／便签的资料夹 | 下一步与继续入口可见；继续进入详情，不强制创建会话，不批量打开文件或工具 |
| U05 | 未保存、冲突、迟到响应和关闭面板 | 保留本地草稿；放弃编辑需确认；不自动合并／强制覆盖；迟到成功不覆盖新输入，只有已确认提交才能显示已保存 |
| S01 | 恶意文本／链接／污染字段 | 不执行脚本、不越权导航、不污染对象原型 |
| S02 | 网络与日志观察 | 无插件主动外发；日志不包含规定排除的敏感字段 |
| P01 | 500 资料夹及限额样本 | 在总容量内分页、筛选可用；分别测试单项／总量越界，超过限额明确拒绝 |
| P02 | 连续使用 60 分钟 | 没有无界增长、忙循环、重复事件风暴 |
| P03 | 20 MiB 活跃容量用满及磁盘空间不足 | 阻止增量写入但允许减量编辑、清理和导出；软删除不释放额度；备份／导入空间不足不破坏原数据 |
| C01 | 每个拟声明支持界面的真实安装 | 从正式待发布包安装，不只跑源码或 mock；首发可仅 Windows 桌面端，Web 单独通过后才声明支持 |
| C02 | 最小官方配置 + 一组常见插件组合 | 入口和样式不冲突；未测试组合如实列明 |
| C03 | P1 关键入口及存储原语探针 | 消息身份／收藏入口、文件选择／预览、工作区上下文及切换、结果确认和整体提交均有目标版本实测；不可用能力明确阻塞或按方案降级 |

## 4. 初始性能预算

只测插件带来的增量，并记录同机关闭插件的基线：
- 面板首次打开：本地已有数据时 p95 不超过 500 ms。
- 小型编辑保存：本地存储 p95 不超过 200 ms。
- 活跃插件不产生持续后台轮询；界面关闭后无自身搜索／扫描任务。
- 大输入解析不在主线程产生持续卡顿；若出现重复长任务，缩小输入或转移到可取消 Worker。
- 内存：固定数据集做多轮相同操作，比较释放后的趋势；只报告绝对增量和曲线，不把一次 GC 后下降当作无泄漏证据。

这些预算需要在目标机器校准。无法稳定计时的 CI 项目作趋势警报；真实机器的持续卡顿、增长或阻塞作为发布阻断，不用平均值掩盖。

## 5. 测试组织

1. 纯逻辑测试：引用校验、限额、导入、冲突、schema。
2. Host 集成测试：真实存储、Remote 校验、生命周期和取消。
3. 真实 DSH 安装与 UI 测试：使用合成会话验证导航、保存和恢复。
4. 故障注入：仅在可丢弃环境测试写失败、坏数据和加载失败。
5. Release 包测试：pack 后解包核验、安装、升级、回退、卸载。
6. 人工检查：Windows 桌面、中文、键盘导航、暗色主题与窄窗口。

通过类型检查／单元测试不能替代第 3、5 项。未完成的检查写“未验证”，环境阻塞与实现失败分别记录。

## 6. 发布流程

1. 确定候选 commit、版本、兼容范围和 schema 版本。
2. 复核变更、依赖、第三方许可及安全敏感代码。
3. 在干净环境按锁文件构建；检查发布文件白名单。
4. 生成候选 tarball，完成实际安装与升级／回退验证。
5. 为最终包生成 SHA-256、依赖清单及测试摘要；最终包字节应与测试包一致。
6. 人工批准受保护发布流程，再创建 GitHub tag 与 Release。
7. 如需 npm，核对命名空间和发布身份，固定包版本；不提供跟随 main 的默认安装方式。
8. 保留上一已知可用包与迁移说明；发布后问题通过 Issue 收集，不偷偷热替换同版本包。

供应链要求：
- GitHub Actions 使用最小权限，第三方 Action 固定 commit。
- 不让不可信 PR 在有发布密钥的上下文中执行。
- 发布优先平台支持的可信身份方式；否则保护短期或受限凭据。
- 发布包白名单排除测试会话、诊断、截图隐私、密钥、用户配置和开发机器路径。
- 默认不需要安装期下载器、自更新器或特权安装脚本；若依赖引入脚本，要单独评审说明。

## 7. 更新与回退策略

默认由用户通过宿主选择固定版本更新，不自建无人值守更新器。更新前展示支持宿主版本、变更、迁移需求及已知问题。

迁移失败：不覆盖旧数据；提示失败阶段，允许导出／恢复。  
新版代码故障：停用并安装上一已知可用版本，但先检查数据格式是否兼容。  
新格式无法降级：保留新数据备份，展示恢复旧快照的损失范围，用户选择后恢复。  
恢复失败：保持原始材料，停止自动重试，输出可操作诊断。

官方更新管理器已有检查和部分恢复行为，但其恢复可能失败，也不会自动保证本插件数据迁移可逆。因此实际演练不能省略。

## 8. 发行记录格式

每次 Release 附一张简表：
- 插件版本、commit、包文件及 SHA-256；
- 测试过的 DSH／系统／界面组合；
- 通过、失败、未验证的检查编号；
- schema 变化与回退条件；
- 已知问题、依赖变化、许可证记录；
- 恢复入口与 Issue／安全报告链接。

遇到导致数据损坏、宿主无法启动或敏感数据泄露的问题，阻断新发布并标记受影响版本。不要简单删除所有旧包让用户无法恢复；保留必要证据，给出撤回或停用指导。
