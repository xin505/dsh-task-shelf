# 安全与稳定性设计

状态：方案 v0.2 的设计要求，尚未实现或验证。数据、容量、写入和导入契约以 [V1-PLAN.md 第 5–6 节](V1-PLAN.md#5-数据模型与限额) 为准。

## 1. 信任模型

DSH 官方插件管理文档明确：宿主插件在同一进程内、工作区沙箱外执行。我们控制自己的代码行为，无法仅靠一个普通插件为自身提供不可绕过的权限隔离。

必须区分：
- **代码约束**：不调用 shell、不外发数据、不改源文件，由源码审查和测试验证。
- **权限隔离**：操作系统、独立进程沙箱或宿主强制限制。第一版没有新增这种保证。
- **故障隔离**：UI 错误边界、Worker 和错误处理只能覆盖对应故障；无法保证拦住模块导入异常、全局资源耗尽或同线程死循环。

本项目不能防御已经能任意修改 DSH 或用户文件的恶意本机程序，也不能约束另一个同权限插件。README 必须保持这些边界可见。

## 2. 数据与访问范围

| 对象 | 允许用途 | 首版限制 |
|---|---|---|
| 会话元数据 | 用户选择关联项、导航、检查引用是否存在 | 按需读取，不批量索引聊天正文 |
| 用户选中的消息 | 验证引用并保存短摘录 | 不收集隐藏推理、不自动读取工具输出 |
| 文件引用 | 保存工作区相对路径并调用原生预览 | 不增加文件内容读取或写入接口 |
| 插件记录 | 资料夹、便签、引用和迁移状态 | 独立命名空间，禁止写入 DSH 会话存储 |
| 导出文件 | 用户主动备份和迁移 | 导出前显示范围，允许去除摘录与便签 |
| 运行日志 | 错误码、数量、时长、兼容状态 | 默认不记正文、密钥、环境变量、绝对路径 |

首版没有遥测、远程字体、第三方 CDN、联网更新器或分析服务。用户主动打开外部链接应走明确的用户动作和协议校验。依赖包的联网行为也属于审查范围。

## 3. 风险与控制

| 风险 | 控制 | 验证方式 |
|---|---|---|
| 包加载失败拖累启动 | 无顶层 I/O；小入口；仅追加自己的可选扩展；无覆盖核心插件的 patch | 隔离环境注入导入／初始化失败，观察宿主状态和恢复路径 |
| 异步异常导致宿主退出 | 注册回调捕获自身错误；所有 Promise 有明确归属；不修改全局异常策略 | 注入拒绝、取消与超时；检查无未处理拒绝 |
| UI 卡顿／内存增长 | 懒加载、分页、限制输入大小、取消过期请求；需要时使用可终止 Worker | 固定样本、连续开关／切换测试、内存及长任务测量 |
| 保存覆盖或损坏 | Host revision 检查；原子提交；有效备份；失败保留原数据 | 双窗口竞争、异常退出、存储写入失败 |
| 提交成功但响应丢失 | operationId、持久化幂等回执、授权后的结果查询；超时显示结果待确认 | 提交后断连／重启，再用原标识查询或重试；回执过期和容量耗尽 |
| 分块导入造成半批数据或重复记录 | 有界暂存、块序号及摘要校验、用户确认映射、最终整体提交和持久化导入回执 | 重复块、缺块、取消、提交中断、重复包及并发编辑 |
| 越权引用或路径穿越 | 在 Host 端校验工作区、会话和引用归属；来源与本地绑定分离；文件路径限制及规范化 | ../、绝对路径、跨工作区、符号链接、伪造 ID 和来源标识测试 |
| 摘录／导入内容导致 XSS | 纯文本输出，禁止危险 HTML；导入 schema 与大小验证 | 脚本标签、事件属性、恶意 URL、特殊 Unicode 样本 |
| 导入原型污染／重复 ID | 白名单字段映射、不合并任意对象；生成本地 ID；解析后再次校验 | __proto__、嵌套超限、碰撞 ID、未知 schema |
| 供应链污染 | 少量依赖、锁文件、来源许可核验、固定版本构建、审查发布差异 | 包内容清单、依赖扫描、来源与构建日志检查 |
| 日志／公开问题泄露 | 最小日志；诊断预览后导出；合成测试数据 | 检查日志与发布包中不含真实对话、凭据和本地路径 |
| 升级数据不可读 | schema 版本检查；迁移前备份；旧版本拒绝写未知新 schema | 升级失败与代码回退后的数据访问演练 |

“私有路由”“仅本机”不能替代授权检查。复用 DSH Remote/连接认证后，仍需要检查请求对象所属工作区；不能仅相信客户端发来的 sessionId 或路径。导入包的 originId、导出 ID 和内容摘要都不是认证依据；来自本机的声明也不能跳过重新授权。引用暂不可验证不等于已删除，不能因此清除摘录或备注。

容量边界分层执行：普通请求保持 64 KiB 上限；32 MiB 导入先按大小拒绝超限输入，再在受限执行路径解析和校验，不能在 Host 主线程进行无界解析。分块后的编码与封装同样计入请求上限。暂存、候选数据、备份及幂等回执各有独立配额和清理策略；完整导出须可被同版本重新导入，额度耗尽仍保留导出与结果查询路径。

## 4. 初始化、运行与退出

初始化顺序：
1. 由宿主执行声明式版本准入。
2. 最小入口注册上下文和能力，不读取大批数据。
3. 校验公开接口与存储格式。
4. 挂载 UI 入口及按需读取服务。
5. 用户打开面板后分页加载内容。

服务不可用时显示插件内错误；不挂全局错误处理器吞掉宿主异常，不无限自动重试。

后台索引、扫描与轮询首版为零。必要的事件订阅经 ctx 生命周期管理；任何原生定时器、AbortController、Worker、对象 URL 和 DOM 监听都明确登记释放。退出时设置有限等待时间，取消自身任务，避免无限 await 阻塞卸载。

初始请求超时目标 5 秒，仅适用于可取消的异步操作。Promise 超时不会停止同步死循环；Worker 任务超过时限需真正 terminate，Host 不做不受限同步解析或正则计算。超时或取消等待不代表已提交事务回滚；写入结果不明时保留原 operationId，提供按需结果查询，不自动生成新操作重做。导入暂存保留期、幂等回执保留期和容量上限在 P1 固定并验证，过期不得冒充“从未执行”。

## 5. 数据损坏与回退

- 发现坏数据：保留原始文件／记录，进入只读恢复状态；不以空数据覆盖。
- 写入明确失败：不报成功；保留 UI 输入，允许复制或导出可读取部分。仅响应丢失时显示“结果待确认”，按写入协议查询，不直接判定失败。
- 导入：暂存与正式集合分离；确认前取消不改正式记录，最终提交把全部候选记录和回执一起生效。崩溃恢复不得留下可见的半批记录或重复执行已提交作业。
- 新 schema：旧插件拒绝写入，提示使用匹配版本或从备份恢复。
- 迁移：先验证备份可读，再生成新数据并校验，最后原子切换；无成功切换则仍使用旧完整数据。
- 备份可包含敏感便签。采用当前用户的数据目录，遵循已有访问控制；不宣称有额外加密。
- 回退代码不等于回退数据。恢复旧备份会丢失备份之后的修改，必须展示影响并由用户选择。
- 正常卸载只停用代码；保留插件数据需通过实际安装机制确认。独立“清除本插件数据”入口才负责删除。
- 不自动修改用户权限、兼容豁免、沙箱或宿主全局配置。

## 6. 宿主启动失败的外部恢复

本插件不能在自身无法加载时可靠修复自身。发布前必须验证脱离插件 UI 的恢复方式：
- 官方桌面端：针对受支持发行版验证原生“禁用第三方插件并重启”入口。
- Web：根据同版本 CLI 的官方管理命令停用或移除本插件，必要时重启。
- 操作之前保留插件数据及 profile 的必要备份；不把“删除整个 DSH_HOME”作为恢复步骤。

文档中的具体命令必须来自已测试版本，不用未经验证的通用命令代替。恢复入口可能禁用其他插件，要清楚说明实际影响。

## 7. 发布前安全声明

可以写：“在列出的版本组合上，通过了所列测试；插件默认无外发网络、仅写自身存储。”
不可以写：“100% 安全”“不会崩溃”“安装包有哈希所以代码可信”“使用官方接口所以永久兼容”。

哈希只能帮助校验包是否与发布记录一致；签名和来源证明仍不代替代码审查。
